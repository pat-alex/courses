# منصة التدريب الإلكترونية

موقع تدريبي بسيط (وحدات ← موضوعات ← اختبار قصير)، بيسجّل دخول المتدربين
وتقدمهم في Google Sheet، ومصمّم عشان يترفع كـ ملفات ثابتة على GitHub Pages.

## 1. هيكل الملفات

```
index.html                     ← صفحة تسجيل الدخول
course.html                    ← صفحة عرض الوحدات/الموضوعات/الاختبار
assets/css/style.css           ← التصميم
assets/js/config.js            ← محتوى الكورس (وحدات/موضوعات/اختبارات) - ده اللي هتعدّل فيه غالبًا
assets/js/api.js               ← الاتصال بجوجل شيت (فيه رابط لازم تحطه)
assets/js/auth.js              ← منطق صفحة تسجيل الدخول
assets/js/app.js               ← منطق صفحة التدريب والاختبارات
google-apps-script/Code.gs     ← الكود اللي بيتنشر على جوجل شيت كـ Web App
```

## 2. إعداد Google Sheet + Apps Script (مرة واحدة بس)

1. افتح [Google Sheets](https://sheets.google.com) واعمل شيت جديد، سمّيه أي اسم
   (مثلاً "بيانات المتدربين").
2. من القائمة العلوية: **Extensions ← Apps Script**.
3. هيفتحلك محرر أكواد فيه ملف `Code.gs` فاضي تقريبًا. امسح اللي فيه، وافتح
   ملف `google-apps-script/Code.gs` من المشروع ده، وانسخ محتواه بالكامل
   والصقه في المحرر.
4. احفظ (Ctrl+S)، وبعدين اضغط **Deploy ← New deployment**.
5. من إعدادات النشر:
   - **Select type** اختار "Web app".
   - **Execute as**: Me (حسابك).
   - **Who has access**: Anyone.
6. اضغط **Deploy**، وهيطلب منك تأكيد صلاحيات — وافق عليها (هتظهر رسالة تحذير
   من جوجل لأنه سكريبت مكتوب من حسابك، اضغط "Advanced" ثم "Go to ... (unsafe)"
   واستمر، ده طبيعي لأي Apps Script جديد).
7. بعد النشر هيديك رابط شكله شبه:
   `https://script.google.com/macros/s/XXXXXXXXXXXXXXXXXXXXXXXXX/exec`
   انسخ الرابط ده.
8. افتح ملف `assets/js/api.js` في المشروع، ولاقي السطر:
   ```js
   const APPS_SCRIPT_URL = "PUT_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
   ```
   واستبدل النص بالرابط اللي نسخته.

> **ملحوظة:** أي تعديل لاحق في كود `Code.gs` لازم تعمله بعد كده **Deploy ←
> Manage deployments ← ✏️ تعديل ← نشر نسخة جديدة (New version)** عشان
> التعديلات تنعكس على الرابط.

الشيت هيتكوّن أوتوماتيك من تبويب اسمه **Progress** بالأعمدة التالية أول ما
حد يسجّل دخول لأول مرة:

| Code | Name | LastUnitId | LastTopicId | CompletedUnits | QuizScores | LastUpdated |
|------|------|------------|-------------|-----------------|------------|-------------|

## 3. إضافة/تعديل محتوى الكورس

كل المحتوى (عنوان البرنامج، الوحدات، الموضوعات، أسئلة الاختبار) موجود في
ملف `assets/js/config.js`، والملف فيه شرح تفصيلي جوه بالتعليقات. ملخص:

- **موضوع نصي**: `{ id, type: "text", title, body }` — `body` ممكن يحتوي
  HTML بسيط زي `<p>` و `<ul><li>`.
- **فيديو يوتيوب**: `{ id, type: "video", title, youtubeId, description }`
  — `youtubeId` هو الجزء اللي بعد `v=` في رابط الفيديو.
- **ملف من درايف**: `{ id, type: "file", title, driveFileId, description }`
  — `driveFileId` من رابط مشاركة الملف
  (`.../file/d/<هنا الكود>/view`).
  **لازم** تغيّر مشاركة الملف (أو الفولدر اللي عليه) إلى "أي شخص لديه
  الرابط يمكنه العرض"، وإلا الملف مش هيظهر للمتدربين.

كل وحدة لها `quiz.questions` — مصفوفة من 5 أسئلة، كل سؤال:
```js
{ question: "نص السؤال؟", options: ["أ", "ب", "ج", "د"], correctIndex: 0 }
```
`correctIndex` هو رقم ترتيب الإجابة الصحيحة جوه `options` (بيبدأ من 0).

الحد الأدنى للنجاح في الاختبار متحكم فيه من `quizPassingScore` أعلى ملف
الإعدادات (افتراضيًا 3 من 5).

## 4. رفع الموقع على GitHub Pages

1. اعمل Repository جديد على GitHub (Public).
2. ارفع كل ملفات المجلد ده (بنفس الهيكل) على الـ Repository.
3. من إعدادات الـ Repository: **Settings ← Pages**.
4. تحت "Build and deployment": اختار **Deploy from a branch**، وبعدين
   اختار الـ branch (غالبًا `main`) والمجلد `/ (root)`.
5. احفظ، واستنى دقيقة أو اتنين، وهيديك رابط الموقع شكله شبه:
   `https://<اسم-حسابك>.github.io/<اسم-الريبو>/`

## 5. طريقة عمل الحفظ والاستكمال

- عند تسجيل الدخول، المتدرب بيدخل اسمه وكوده التعريفي. لو الكود موجود
  قبل كده في الشيت، الموقع بيرجّعه لنفس آخر موضوع أو اختبار كان واقف
  عنده.
- الموقع بيحفظ آخر نقطة توقف **تلقائيًا مع كل تنقل** بين الموضوعات (مش
  مرة واحدة بس آخر اليوم) — ده أضمن، لأنه لو المتدرب قفل المتصفح فجأة
  ما يضيعش تقدمه.
- التنقل بين الوحدات والموضوعات من الشريط الجانبي متاح بحرية (مش مقفول
  بالترتيب)، لكن نقطة "متابعة" التلقائية بترجّعه دايمًا لآخر حاجة وصلها.
- درجات الاختبارات بتتحفظ لكل وحدة، والوحدة بتتعتبر "مكتملة" (نقطة ذهبية)
  لما المتدرب يحقق الحد الأدنى للنجاح.

## 6. تجربة الموقع محليًا قبل الرفع

تقدر تفتح `index.html` مباشرة في المتصفح للتجربة، لكن بعض المتصفحات بتمنع
طلبات `fetch` من ملفات مفتوحة مباشرة من الجهاز (`file://`). الأسهل: استخدم
أي سيرفر محلي بسيط، مثلاً في الطرفية:
```
npx serve .
```
وبعدين افتح الرابط اللي هيديهولك (`http://localhost:...`).

## 7. أفكار للتطوير لاحقًا (اختياري)

- ربط زر "تسجيل الخروج" بتنبيه تأكيد.
- إضافة شهادة PDF تلقائية عند إنهاء كل الوحدات.
- عرض تقرير لكل المتدربين مباشرة من الشيت (Pivot table أو Google Data Studio).
